# 有界改路与漏检复盘

遇真实失败、旧阻断变化或已修/已验后再发现问题时读取。定位同一失效条件，不扩成永久全量审计，不从项目授权推导额外部署或记忆权限。

按本页适用条件选用检查，不把某一场景的流程升级为所有任务的默认步骤。

<a id="legacy-l142"></a>

遇到失败或待决项，先用最新代码、实际配置和本轮证据确认根因与影响范围，区分程序缺陷、外部权限/能力缺失、验收数据未到和用户业务决定。不要沿用已解除的旧阻塞，也不要把一个单元的缺项扩大为整个目标无法推进。

<a id="legacy-l144"></a>

遇到错误，应主动核实实际调用、运行状态与原始响应，写明待验证假设，再在现有授权和有限预算内更换入口、来源或请求方式作有界验证；逐次记录条件差异、结果和停止原因，同因无新证据不原样重试。换方法不扩大费用、权限、交易或外发边界。

<a id="legacy-l146"></a>

在现有授权内自主选择能保持业务目标与约束的替代路径：更换诊断入口或可用来源、复用真实保存证据、修正错误依赖，或先交付可独立验收的纵向功能。只拆开本来不同的要求，不能把必需安全事实移出准入门禁；新增费用、资金风险、破坏性操作或权限扩大仍需用户决定。实现、运行和晋级资格分开记录，替代路径不能倒填历史证明或资格时长。

<a id="legacy-l148"></a>

改路前写明原路径为什么不可达、替代方案满足哪条验收标准及尚缺什么；按风险做最小验证，成功后接回原目标继续执行，不积累仅被测试调用的孤立组件。尚未证实等价时保留原单元未通过状态。

<a id="legacy-l150"></a>

不要等机械重试次数耗尽才换方案。同因重试没有新证据时就重新检查假设、日志与入口；连续三次无新增证据必须停止原样重试。只在全部剩余可推进路径确实依赖外部输入时才整体阻塞，并一次说明具体缺项、已排除的替代方案和解除条件；不要重复询问已授权事项或用进度最终答复等待用户说“继续”。

<a id="legacy-l156"></a>

同一任务在修复、验收或部署后再次发现缺陷时，自动执行漏检复盘，不等待用户再次要求。先与上轮缺陷、源码版本、测试用例和执行证据对照，区分旧缺陷未覆盖、修复引入回归、新环境/输入暴露，以及原已声明的未验收限制；新发现不自动等于上次修复失败。

<a id="legacy-l158"></a>

在原账本记录两条因果链：

<a id="legacy-l160"></a>

- **缺陷根因**：触发条件 → 实际代码/配置行为 → 错误输出或副作用。
- **漏检根因**：上轮检查了什么 → 哪个输入、分支、真实入口、运行层级或断言缺失/错误 → 为什么当时仍被判通过。引用具体 T/E、文件或日志；证据不足标为待核实，不能用“测试不够”代替分析，也不能编造上轮执行情况。

<a id="legacy-l163"></a>

针对漏检原因补一项能重现遗漏的测试或运行核验，再修复、重测；依据同一个失效条件检查直接相关入口和分支，避免只修当前报错点，也不扩展成无限全面审计。上轮已有测试却未发现时，检查夹具是否预设未知为安全、断言是否只看返回码/外层成功、真实用户入口是否跳过、测试版本与运行配置是否一致。没有新增风险或改动依据时不反复扩大测试。

<a id="legacy-l165"></a>

同一验收结论若同时从 CLI、API、网页、定时任务或其他入口提供，必须共享同一判定函数，或用契约测试逐项证明各入口等价；不能在入口层分别追加门禁后只测试“接口可调用”。至少断言本次新增或修正的判定条件在每个承诺入口均生效、同一反例均被拒绝。若本轮包含已授权部署，再读取部署后的真实用户入口验证；仅获本地修复授权时，按本地层级交付并列明未部署状态。

<a id="legacy-l167"></a>

复盘必须关联缺陷 ID、上轮证据、新增 T/A、修复、重测 E 与剩余未验收项。最终交付简短说明“为什么上轮没发现、此次增加了什么防线、实际验证到哪层”。不能把重复修复次数或测试数量当成可靠性证明。

<a id="legacy-l169"></a>

先将具体案例和执行证据保存在项目，把守护放在最早且稳定能判别该错误的位置：确定性行为用回归测试或脚本，项目环境与操作约定写入项目说明，反复使用且可复用的流程再提炼为技能；确需持续阻断的通用可判定约束按项目需要接入 CI。先检查已有规则并补缺口或合并重复项，不把每次问题都追加成所有任务的长条款。

用户要求总结入技能时，只提炼本次有证据支持的通用决策规则，记录版本并验证。写长期记忆必须有用户明确授权并使用环境规定的记忆入口；未授权时不自行写记忆，也不让复盘替代修复任务或扩大部署权限。
