# 外部字段、来源与回退契约

只在依赖外部事实、接口或来源回退时读取。正面结论要匹配实际对象、协议、时点与采用来源；探针不扩大预算或授权。

对象维度来自当前项目契约，例如文件/版本、租户/资源或协议/对象ID；不预设链、CA、钱包或交易池。下文这些领域例子只有在实际接口具有相应维度时才启用；保留“对象、范围、时间与来源对应”的方法，不将某个业务的数据模型强加给其他接口。

按本页适用条件选用检查，不把某一场景的流程升级为所有任务的默认步骤。

外发结果需要诊断时，先检查共用发送入口是否保留本次调用可得的安全类别、失败阶段、实际耗时、退出码及输出摘要/长度；无响应与空响应分开。优先使用这些安全摘要，不得无筛选持久化可能含秘密的输出；可按项目约定保留已经脱敏的具体错误。诊断落盘失败不得改变投递事实或触发未知结果重发。历史缺少关联证据就保留原因未知，附近日志只能作为待核实线索；不靠再次外发补证。

<a id="legacy-l046"></a>

自有HTTP诊断探针在响应体积或解析检查前，先留存已经取得的安全事实：状态码、Content-Type、可选声明长度、实际读取的有界字节数及失败阶段。未取得响应时明确未取得，缺失元数据不补猜；超限标为截断、正文未验，不为补证自动加限或重放同请求。只记录必要脱敏投影，不输出完整headers或秘密；探针预算服从本次任务，不把案例阈值升级为全局API限制。

<a id="legacy-l054"></a>

外部数据字段必须建立“请求成功 → 响应字段存在 → 值非空 → 语义已验证 → 标准化映射 → 持久化 → 决策使用”的覆盖链。HTTP 200或业务成功包只证明接口响应，不能证明某个指标可用；字段存在但长期返回`null`、哨兵值或空对象时要单独统计。用至少一份真实录制响应验证字段名和类型，避免测试夹具沿用实现自造字段而同时出错。`unknown/null`、数值`0`、布尔`false`和空列表必须分别建模，未采集不得硬编码成零或“没有风险”。性能优化或缓存不得缩窄原 selector/claim 允许的任务输入域；应以真实领取形状覆盖合法 nullable 组合，原任务合法而仅不满足复用条件时保留原处理路径。

<a id="legacy-l060"></a>

多源合并分别验证数值与实际采用来源（owner）。外部事实同值不等于来源未知，不能抹去已知采用来源；未知owner也不得凭相等备用事实升级为已证明来源。沿真实合并→采用→历史存储/读回入口断言被采用来源的身份、方法和时间仍可追踪，并覆盖已知owner/备用同值、未知owner/已知备用同值两个反例。

<a id="legacy-l064"></a>

当备用执行成功但首路失败时，验收须分别保留成功执行证明与首路诊断，并穿过真实collect→存储→读回入口。检查区块/来源/身份及数量单位；大整数不能先经浮点转换，证明的实质内容应进入证据身份，缺少历史证明不得凭通过状态补造。

<a id="legacy-l066"></a>

每个外部响应解析测试必须标明字段结构依据：官方Schema、脱敏真实录制响应或两者同时存在。不能用实现作者手写的理想化夹具作为唯一契约证据。若请求参数已经限定业务类型而响应项不重复该类型字段，测试要覆盖这种真实结构，解析器不得再次要求不存在的判别字段；若由多个返回字段计算金额、比例或风险，至少加入一份使用官方字段名的计算用例，并把尚未出现过的真实事件标为运行观察未验收。

<a id="legacy-l068"></a>

当外部CLI/插件/网关回执与预期不符时，沿底层结果到实际CLI输出核对删字段、平铺或重命名的中间转换；只测首尾纯函数不能证明中间层保留身份。源码派生夹具标明截断边界，磁盘源码不冒充已加载版本。真实外发测试为该调用保留有界脱敏结构投影（键、类型、成功标记、消息ID、目标字段存在性）并以请求/消息摘要关联，不保留任意stdout/stderr、秘密或正文，不为取证重发未知结果。无目标回显与显式错目标分开建模，是否可判成功依实际契约，不伪造平台确认。

<a id="legacy-l070"></a>

引入替代Provider或降级路径时，必须从真实编排入口反查旧Provider专属的前置条件、提前返回和失败分支；替代组件可用但在执行前被旧源门禁截断，不能算已接管。至少加入一条“旧主源失败、替代源成功”的入口测试，并确认缺失安全事实仍按未知关闭。

<a id="legacy-l072"></a>

当一个外部字段可能改变安全门禁、资金决策或资格分类时，再验证它在目标链、目标协议和目标时间语境中的含义。名称相近不能替代语义证明，例如“首笔代币转入来源”不能直接冒充“Gas资金来源”。语义未验证的字段可以保存为实验事实或明确失败证据，但不得据此生成正面安全结论。

<a id="legacy-l074"></a>

复用证明构建器且其支持多种合法完整性模式时，正面结论的调用方必须明确校验获批的具体模式及其完整性条件，不能只凭通用`valid/complete`放行。补一条“旧模式本身有效，但不满足本次调用方要求，仍应拒绝正面结论”的反例，并沿保存→读回→实际消费者验证，防止持久化后的泛化状态恢复放行；检查限于本次调用链。发布前发现的候选契约缺陷单列，不计作线上bug。

<a id="legacy-l076"></a>

对外部Provider的“能力存在”分四层记录：官方产品/API家族是否存在、目标链是否被支持、目标链真实请求是否返回非空字段、这些字段是否足以支持当前业务结论。“代码未接入”“一次响应为空”“目标链不支持”和“接口不存在”不得混写成同一个结论；宣布拿不到或不支持前，至少核对最新官方能力清单并做一次遵守限流的目标链只读探针。

<a id="legacy-l078"></a>

Provider健康验收同时检查**时间语义与记录基数**：限流/冷却必须结合`retry_at`或全局冷却截止时间判断当前是否仍生效，过期事件只作为历史事故展示；带CA、钱包或池ID的请求路径要归并到能力级健康项，不能让每个资源生成永久健康卡片。限流优化必须用真实时间窗统计请求量、429比例和高价值任务是否被挤占，单次成功或当前无冷却不能证明预算合理。

<a id="legacy-l173"></a>

外部调用失败或异常缓慢时，先核实际服务的请求形状与配置，再判定网络或来源能力；按需读取[网络与RPC诊断](network-rpc-diagnosis.md)。用已授权的有限只读探针复现线上客户端，检查可用备用来源是否被编排分支绕过。探针自身的请求头、路由或解析错误应单独纠正，不能冒充产品事故；HTTP成功、空结果、非空业务证据及完整历史能力分别验收。
