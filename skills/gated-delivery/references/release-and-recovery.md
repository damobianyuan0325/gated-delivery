# 发布、复制、运行环境与恢复

仅涉及替换、部署/安装、服务配置或恢复时读取。先以隔离目标形状完成准备与恢复；这不赋予生产发布、重启或读取秘密的权限。

按本页适用条件选用检查，不把某一场景的流程升级为所有任务的默认步骤。

<a id="legacy-l193"></a>

涉及文件复制、持久化或发布工具时，先规范化 `source/destination` 并识别同一路径或已有别名。before阶段冻结原输入清单与批准提案，首写前保存全部目标的独立前镜像或不存在标记；after阶段用不可变前镜像与清单核原输入，用当前目标核批准结果。`source == destination` 时不能要求已批准修改的当前源仍保持旧摘要；备份原件与校验提案分开冻结，不以同一可变路径充当两者。按最终目标形状在假根完整演练复制→after核验，以及末次替换中断后的隔离恢复；失败保留原计划、前镜像和记录，先区分复制失败与核验工具失效，不盲目重复复制或回滚，不扩大权限、审批或任务范围。

<a id="legacy-l200"></a>

涉及部署时分别记录源码版本、运行目录版本、数据库结构和进程实际加载状态。预览迁移清单不等于检查数据库；复制文件不等于进程已加载。先用只读检查把“待核实”变为具体缺项，再决定迁移、发布和回滚步骤。发布或安装工具改变目标数量或目录结构后，也须用最终目标形状验证备份与中断恢复；平面目标演练不能替代包含子目录的实际清单。

<a id="legacy-l202"></a>

发布清单新增包或目录时，隔离恢复夹具须保留实际before中父目录缺席的形状，不能为测试方便预建而掩盖部署前置条件。若部署负责创建目录，验证完整应用及末次替换失败后的恢复；被替换、非空或归属不明的目录保留并明确人工恢复限制，不以递归清理未知内容冒充完整恢复。

<a id="legacy-l204"></a>

在采集有新鲜期的发布凭据前，先只读核对证据与WAL父目录的存在、路径归属和工具前置条件；缺席时仅在已批准范围内明确创建，再开始新鲜凭据窗口，不能假称原本存在。准备失败先记录是否已建WAL、替换目标或变更服务，再决定下一动作，不盲重试。

<a id="legacy-l230"></a>

若验收包含“网页可访问、服务持续运行、重启后可用”，临时前台进程或一次HTTP 200不能作为最终证据。必须检查实际进程管理器是否已安装并加载、监听地址是否符合授权范围、运行目录是否允许后台进程访问、异常退出是否可见，并在托管进程上重新验证健康端点和用户页面。macOS LaunchAgent 不应直接依赖可能受隐私控制限制的 Documents/Desktop/Downloads 工作目录；部署副本与源码版本必须可追踪。

<a id="legacy-l232"></a>

macOS按本用户核进程时，`ps -U`按真实UID筛选，而`uid`输出列可能是有效UID；先用不含参数的数字列确认目标平台含义，再用`ruid`列逐行严格比较同一真实UID，保留外UID拒绝，不混淆提权辅助进程与跨用户。固定已知入口的扫描仅证明该范围，不输出原参数或环境，也不冒充全部writer覆盖。

<a id="legacy-l234"></a>

验证必须使用目标进程实际的配置来源。文件验证通过不能证明钥匙串、环境变量或服务配置一致；发现不一致时，只报告存在性/一致性结果，不展示秘密，按授权同步后重验。 未显式指定配置路径时，沿实际启动命令、参数缺省值和加载函数确认最终文件或包资源；同名文件、常用目录或旧身份记录不能替代实际入口。用于发布或规则身份的配置须分别核对显式路径与缺省分支，未使用的配置仅记为闲置，不作为运行门槛依据。
