# 验收预期、环境与证据上限

用于设计用例、层级、环境/凭据、交接冻结和覆盖审计；不是要求小编辑都写测试。先有独立业务预期，再让实现与测试接受它；已有有效测试不必全 RED。

按本页适用条件选用检查，不把某一场景的流程升级为所有任务的默认步骤。

<a id="legacy-l040"></a>

每个开发单元开始前，先明确对应验收标准和检查方法，不要求把整个大项目的全部测试代码一次性写完。可自动判定的 A 映射到有效的现有检查，缺失时再补检查；主观体验、重要业务取舍和自然观察则记录人工复核或观察方法、接受者、实际证据与未满足条件。并非每条标准都要写成测试函数，自动检查通过也不能代替尚未完成的人工接受或观察。人工记录沿用项目账本，不向现有 JSON 合同添加工具不支持的字段。

<a id="legacy-l042"></a>

每个用例必须包含：关联标准、测试层级、前置环境、输入/夹具、执行动作、精确预期、断言位置、运行命令、清理办法。拒绝以“正常”“没问题”“看起来可用”作为预期。

<a id="legacy-l044"></a>

按风险选择单元、集成、API、数据库、端到端、UI、性能或安全测试。涉及接口时验证状态码、结构和业务语义；数据库验证事务与约束；异步行为明确期限和最终状态；页面验证关键交互和可见结果，而非只检查页面返回 200。

<a id="legacy-l090"></a>

对重要行为覆盖正常、边界、失败路径；涉及重复执行、并发、外部状态、权限或恢复时增加对应测试。不要为了数量编写无意义排列组合。

<a id="legacy-l094"></a>

测试应来自需求，不能仅复制实现逻辑作为预期。缺陷修复先重现；新增行为尽量先运行能暴露缺失行为的测试，确认失败原因正确。尚无测试基础时可先搭最小测试设施，但不能伪造“先失败”的记录。

<a id="legacy-l098"></a>

以源码文本作为契约断言时，搜索范围必须收窄到目标类、方法、分支或调用链，并先在缺失实现上证明断言会失败；全文件出现同名SQL、字段或函数不能证明目标路径已接线。关键持久化行为优先使用可观察的写入/读回测试，源码断言只能补充结构约束，不能让其他入口的相同文本替目标入口误通过。

<a id="legacy-l104"></a>

复合验收标准必须拆成可独立判定的子标准（如 A08.1、A08.2），逐项记录证据。一个子句通过不能使包含“并且/以及/从而”的整项自动通过；外部依赖、自然时长或样本量未满足时，框架代码完成只能记为实现完成，不能记为验收通过。

<a id="legacy-l106"></a>

为每个单元同时记录三类状态：**实现状态**（代码是否存在）、**验证状态**（是否达到指定测试层级）、**运行观察状态**（是否在真实调度、数据和时长下发生）。项目队列仍使用 `TODO → READY → IN_PROGRESS → VERIFYING → PASSED`，但 `PASSED` 仅允许所有必做子标准在要求层级通过；否则保持 `VERIFYING`、`BLOCKED` 或拆出后续单元。

<a id="legacy-l177"></a>

每次重要测试记录：命令、环境、代码版本或文件摘要、开始时间、退出码、通过/失败/跳过数量、脱敏输出路径、关联 T/A/U。

<a id="legacy-l179"></a>

准确回归还应核对实际执行的解释器入口、`sys.executable`、`sys.prefix`及必要环境身份；两个入口指向同一底层Python二进制，不代表同一虚拟环境或依赖。计量或审计自身失败、缺项或覆盖不全时，显式标为`unavailable/incomplete`并保留已知范围，不能把未记录的计数以0冒充完整采集。复用runner先核测试声明的输出环境变量名和产物路径；完整包清单与代码子集沿下文既有摘要范围规则分别核对，结果收集失败不计作产品失败。

<a id="legacy-l181"></a>

Python候选与已安装代码并存时，配置加载器或数据库连接器可能改变导入路径和模块缓存。完成获批配置与连接初始化后，在首个业务调用或SQL前核对被测模块的实际`__file__`归属及关键接口签名，并覆盖后续懒加载；实际配置源码与候选业务源码分别记录。混源引起的参数或属性错误先修验收工具，不改产品、移除校验或复制秘密来求绿。

<a id="legacy-l183"></a>

从既有工程挑选用例放入精确运行包时，沿被选用例实际导入链核对测试支持模块和录制夹具，先在声明的根完成只收集检查。缺依赖时保留首次收集失败和原包清单，补入未变支持文件；不改产品或断言，也不临时借未声明的工程路径求绿。仅补测试包装依赖不重新生成产品源码、版本或发布身份。

<a id="legacy-l185"></a>

重新验收产生新修订凭据时，发布工具应按本次明确冻结的路径和摘要绑定它；不要假定成功结果仍使用旧文件名，也不要覆盖保留的失败凭据来适配工具。变更工具后先验证无副作用入口和恢复，再执行。

<a id="legacy-l187"></a>

摘要或清单校验先明确文件范围与规范化方式，分别命名原文件字节、规范SQL和可执行子集，禁止将不同范围直接比较；校验工具拒绝不能冒称运行源码漂移。 带域前缀或规范化的身份应调用实际已 pin 的构造器验证，并分别命名身份摘要与规范 payload SHA；不得手写裸 JSON 摘要替代身份。

<a id="legacy-l189"></a>

已交接为 READY/待执行的源码、脚本、计划与凭据应冻结；修改后须重新报告 hash 及受影响验证状态，执行方在实际执行前比对，不能悄悄覆盖已交接材料。

<a id="legacy-l191"></a>

多人并行开发或审阅共用证据目录时，每个产物目录或文件明确唯一写入者，写前检查是否已有原件；独立审阅使用各自目录，以独占创建拒绝覆盖已有文件。重审另建修订目录，保留旧字节和摘要。若已发生覆盖，如实记录缺失，只能从真实备份恢复原字节，不能重构报告冒充旧原件。

<a id="legacy-l195"></a>

- 没运行的写 NOT_RUN；无法访问外部服务的写 BLOCKED；跳过、xfail、mock 不能冒充真实集成通过。
- 明确区分：源码实现、离线测试、集成测试、生产部署、真实运行验收。按需求所要求的层级判定，不强制所有任务做生产部署。
- “有 100 个测试通过”不能证明第 101 个未覆盖的业务路径已完成。检查每条必做 A 是否有有效证据。
- 依赖或代码改变后，重新验证受影响项；旧结果标为待复核。最终回归必须对应最后修改后的代码，不能沿用改动前的全量结果。

<a id="legacy-l258"></a>

证据结论不得超过测试替身的层级：

<a id="legacy-l260"></a>

- fake store / mock provider 只证明组件契约，不证明真实持久化、事务、SQL或外部语义；
- 纯内存端到端只证明领域编排，不得命名或记录为生产持久化E2E；
- HTTP 200只证明接口可达，不证明页面交互、业务内容、响应式布局或性能目标；
- 配置中的周期、TTL和超时不证明实际耗时，带秒数的承诺必须测量；
- 自然运行天数、样本量和真实事件数必须实际观察，不能由测试夹具补足。

<a id="legacy-l266"></a>

最终回归前执行一次“验收覆盖审计”：对每个 A 子标准列出检查或人工/观察方法及 E 证据，自动检查注明断言位置，人工/观察注明接受者与未满足条件；按适用项核对实际入口、存储适配器和触发器，再检查关键类/函数是否只被测试引用而未被运行入口引用。发现关键终态不可达、运行适配器未接线或只有空闲周期时，恢复相关单元为 `IN_PROGRESS/VERIFYING/BLOCKED`，先修复而不是以全量测试通过结束。

<a id="legacy-l268"></a>

功能×平台/链的覆盖矩阵须把证据映射到该功能真实对应的入口和交互（含所需结果表）；周边说明或来源/采集时刻不能替代功能，未实现、无样本、未操作与失败分别记录，未实现仍属需求缺口，不删分母宣称完成。

<a id="legacy-l270"></a>

- 模拟成交不证明真实成交，HTTP 成功不证明业务成功，已授权不证明服务运行，源码目录已改不证明部署目录更新。

## 独立复核

重大、跨边界变更或已出现漏检时，安排独立评审读取需求、实际差分和原始证据，自行追踪关键调用链并核对反例，不能只接受实现者的总结。按风险选择需要重新执行的检查；来源、代码和条件仍有效的证据可以复用，不默认重跑全部检查，也不要求每个小改动采用多代理评审。审阅产物遵守前述独立目录与不可覆盖规则。

## CI 与机器核验边界

本地、隔离、CI、生产及业务效果分别留证。CI 环境/权限/依赖受阻时记录真实缺项；可继续本地独立工作，不将本地结果改名 CI 通过，不关闭 required checks 或 branch protection 求绿。确定性工具只能核声明与凭据，独立 oracle、真实入口及业务结论仍需复核。

分别核实 CI 配置、当前修订实际检查结果、目标分支服务端强制规则及适用范围。任务失败会使流水线失败（例如配置 `allow_failure: false`），仍不证明目标分支已禁止绕过检查；未核实的强制状态单列，不由配置存在推断。

多个变更汇合时，按项目现有机制验证与目标分支组合后的代码，可复用合并队列或临时集成环境，记录被验修订及目标基线。各分支独自通过不证明组合后通过；目标基线变化时重验受影响项，不强制采用某一种合并或变基方式，也不据此取得合并、推送权限。
