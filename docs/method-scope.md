# 方法与资料边界

本仓库用自行编写的操作约定和确定性工具表达通用研发方法：先说明可观察结果与禁止行为，复用现有环境，在授权内实现并验证，保留失败依据，达到约定范围后交付。

## 分发内容

技能入口、按需专题、项目模板、检查与安装脚本，以及合成输入驱动的工具测试。专题中的数据库、网络和资金例子是条件性工程场景；具体系统没有这些条件时不套用相应流程。项目参数来自各项目当前约定。

## 不纳入分发

原始教材和截图、逐页阅读记录、他人团队案例与效率数字、公司或客户事故、私有项目名称和运行轨迹，以及凭据、原始业务数据和安装备份。它们不能因为换了术语就成为可公开内容。

对确实使用的第三方代码、依赖或引用，逐项核对来源、版本、许可证及需要保留的声明；资料范围未确认时不随包分发，也不以删除署名代替审查。仅调整名称不构成权利确认。

## 能证明什么

结构检查能发现一部分文件、链接和敏感内容形状；工具测试证明所覆盖输入下的行为。它们不能保证所有秘密已被识别、所有输入都正确，或具体产品已经验收。效果比较需要本项目实际基线；不承诺统一的交付时长、成本降低或收益。

这些工作约定不是成熟度认证。重要的结果、权限和最终接受仍由任务责任人决定，机器检查只在其真实能力范围内拦截失败。
